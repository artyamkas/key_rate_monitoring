# Мониторинг ключевой ставки ЦБ России на основе многокритериального анализа внешних и внутренних факторов

## 1. Описание проекта

Проект представляет собой систему мониторинга ключевой ставки Центрального банка Российской Федерации на основе анализа внешних и внутренних экономических факторов.

Система предназначена для сбора, хранения, обработки и визуализации экономических показателей, а также построения прогнозов изменения ключевой ставки с использованием методов машинного обучения.

В рамках проекта анализируются следующие показатели:
- ключевая ставка Центрального банка РФ;
- курс австралийского доллара;
- курс дирхама ОАЭ;
- валовой внутренний продукт (ВВП) России;
- торговый баланс России.

На основе собранных данных формируются аналитические графики, рассчитываются корреляции между показателями и строятся прогнозы ключевой ставки.

## 2. Архитектура системы

В проекте используется архитектура с разделением процессов загрузки данных, хранения и визуализации.

Основными компонентами системы являются:

- **PostgreSQL** — централизованное хранилище экономических показателей, истории загрузок и прогнозов.
- **Python Loader** — приложение для получения данных из внешних источников, их обработки и сохранения в базе данных.
- **Scheduler** — планировщик автоматического запуска загрузки данных.
- **Streamlit Dashboard** — веб-приложение для визуализации показателей, анализа данных и просмотра результатов прогнозирования.

Все компоненты запускаются в отдельных Docker-контейнерах. Для загрузчика и веб-приложения используется общий Docker-образ с необходимыми библиотеками Python.

## 5. Развертывание проекта

### 5.1. Требования

Для запуска проекта необходимы:
- Docker;
- Docker Compose;
- Git (если проект загружается из репозитория).

### 5.2. Получение проекта

Клонировать репозиторий:

```bash
git clone https://github.com/artyamkas/key_rate_monitoring
```

Перейти в каталог проекта:

```bash
cd key_rate_monitoring
```

Если проект уже находится на компьютере, достаточно открыть терминал в его корневой папке.

### 5.3. Подготовка конфигурации

В корневом каталоге должен находиться файл `.env` со следующими параметрами:

```env
DATA_TO=ХХХХ-ХХ-ХХ
INITIAL_KEY_RATE_YEARS=3
INITIAL_MACRO_YEARS=3
FIRST_RUN=true
LAST_LOAD_DATE=

POSTGRES_HOST=localhost
POSTGRES_DB=pas
POSTGRES_USER=pas
POSTGRES_PASSWORD=pas_password
POSTGRES_PORT=5444
```

Параметры `FIRST_RUN` и `LAST_LOAD_DATE` используются для управления первоначальной и последующими загрузками.

Для первоначального запуска устанавливается `FIRST_RUN=true` и `DATA_TO`. После успешной обработки всех источников загрузчик самостоятельно обновляет параметры в `.env`.

### 5.4. Запуск системы

Сборка Docker-образов и запуск контейнеров:

```bash
docker compose up -d --build
```

Проверка состояния контейнеров:

```bash
docker compose ps
```

После запуска должны работать три контейнера:
- `pas-postgres`;
- `pas-loader`;
- `pas-dashboard`.

### 5.5. Первоначальная загрузка данных

Планировщик выполняет загрузку ежедневно в 16:00, поэтому для первоначального заполнения базы данных необходимо запустить загрузчик вручную:

```bash
docker compose run --rm loader python src/main.py
```

После выполнения данные будут сохранены в PostgreSQL.

При успешной обработке всех источников параметры первоначальной загрузки автоматически обновятся. При ошибках загрузки параметры не изменяются, что позволяет повторить операцию.

### 5.6. Доступ к дашборду

После запуска контейнеров веб-приложение доступно в браузере:

```text
http://localhost:8501
```

Для просмотра аналитики и состояния загрузок используется боковое меню приложения.

## 6. Управление проектом

Все команды выполняются из корневого каталога проекта.

### Просмотр работающих контейнеров

```bash
docker compose ps
```

### Просмотр логов загрузчика

```bash
docker compose logs -f loader
```

### Просмотр логов дашборда

```bash
docker compose logs -f dashboard
```

### Ручной запуск загрузки данных

```bash
docker compose run --rm loader python src/main.py
```

### Перезапуск контейнеров

```bash
docker compose restart
```

### Остановка контейнеров

```bash
docker compose stop
```

### Повторный запуск остановленных контейнеров

```bash
docker compose start
```

### Остановка и удаление контейнеров

```bash
docker compose down
```

Эта команда удаляет контейнеры и сеть проекта, но сохраняет данные PostgreSQL в Docker volume.

### Пересборка проекта после изменения кода

```bash
docker compose up -d --build
```

### Полное удаление проекта вместе с базой данных

```bash
docker compose down -v
```

**Внимание:** команда удаляет Docker volume с данными PostgreSQL. Все сохранённые показатели, журналы загрузок и история прогнозов будут потеряны.
